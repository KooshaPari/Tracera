# Tracera Agent Work-Maze Boundaries

## Assignment rule

Agents work against the mature contract. They do not invent the denominator, silently add accepted scope, weaken acceptance to fit implementation, or award themselves completion.

A runnable assignment MUST identify:

- canonical FR IDs;
- parent pillar/feature and relevant journey;
- target VP stage;
- dependencies and blockers;
- owner repository/component;
- likely primary/supporting source surfaces;
- forbidden surfaces or ownership boundaries;
- acceptance/oracle intent;
- expected evidence;
- growth disposition and transition constraints.

## Work frontier

The full mature contract establishes the world; an agent receives a bounded frontier selected from it.

Prioritization SHOULD prefer work that:
1. closes essential stage blockers;
2. closes a feature rather than adding another shallow primitive;
3. closes a critical journey;
4. preserves mature-contract boundaries;
5. reduces high transition debt;
6. does not duplicate an existing owner elsewhere in the ecosystem.

## Product expansion vs improvement

Classify work as capability expansion/completion or as quality, performance, usability, reliability, operability, maintenance, migration, refactor, or exploration.

Useful auxiliary work remains valuable but MUST NOT increase core FR completion unless it satisfies an accepted FR.

## Stub-first rule

A stub is healthy when its boundary survives and later stages enrich it. A stub is unhealthy when it creates a second architecture that must later be deleted.

Temporary implementations require:
- explicit `replaceable`, `adapter`, or `prototype_only` disposition;
- estimated replacement/migration burden;
- downstream-consumer awareness;
- expiry stage where appropriate.

## Ownership boundary

Tracera owns product truth and assessment. AgilePlus owns execution/work truth. Source repositories own source content/revisions. Verifiers own measurement results. Tracera may reference and interpret these facts but does not duplicate their native state machines.

## Completion

A work item being closed is not product acceptance. Product state advances only from admissible evidence against the accepted contract.
