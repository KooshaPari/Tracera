# Intent and scope

Tracera is a persistent model of a product and its intended and observed behavior, independent of one checkout, agent or session. It should connect UI journeys, capabilities, requirements, APIs, implementation, dependencies/SBOM, tests, evidence and accepted intent so an operator can explain what the product does, discover a sourced mismatch, assign bounded work and verify its resolution.

Recovered historical intent distinguishes a product graph from a requirements spreadsheet or generic work tracker. The broader ambition includes editing the model to propose changes to the product, maintaining a transactional history and supporting agents without requiring long-tenured human context. Those capabilities remain material obligations; the first useful slice cannot silently redefine the whole product.

| Horizon                             | Required result                                                                                                                                                                | Boundary                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| CVP / first usable MVP              | One actual product, accepted baseline, durable typed relationships, genuine sourced discrepancy, navigable UI, verified repair and restart-safe identity                       | Explicitly limited product/import profiles; manual adjudication allowed                 |
| Mature explanatory product          | Three representative products; versioned model, reliable ingestion and incremental change, explainable search, permission-aware navigation, full published surface disposition | Independently measured correctness, freshness, scale and recovery                       |
| Broader editing/automation ambition | Reviewed model changes generate bounded work/product changes with traceable authorization and outcome                                                                          | No autonomous final effects implied by graph editing; exact execution contract required |

The seed finish request also preserves all-stub completion, truthful page semantics, CLI/MCP/skill workflows, desk CI, hooks, telemetry, authenticated deployment and meaningful dogfood data. Issue [1119](https://github.com/KooshaPari/Tracera/issues/1119) defines a smaller coherent milestone; completing it does not close the wider backlog.

The governing dossier adds independent negative controls, stable IDs, explicit unknown/stale states, source isolation and practical comparator trials. Comparisons must address both traceability systems and simpler manual/search/catalog approaches. Historical competitor names are research candidates, not verified current superiority claims. External work-engine state and canonical product state need distinct owners.

Historical user statements informed this synthesis; no verbatim private dialogue is published. Public review can challenge the scope through the linked specifications, issues and [decision gates](DECISIONS.md).
