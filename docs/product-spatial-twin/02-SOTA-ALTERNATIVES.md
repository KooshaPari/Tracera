## Mature-first gates

Before selecting a renderer or inventing an ontology, establish at least: (a) actual canonical Tracera APIs/geometry requirements; (b) feature matrix for competitors and existing libraries; (c) source/license/version provenance; (d) real software-only and hybrid fixtures; (e) accessibility/mobile/browser constraints; (f) time/memory/task-correctness comparative results; (g) security of imported untrusted scene assets.

## Required adversarial comparisons

- Skeuomorphic assembly vs 2D matrix for high-degree dependency tracing.
- 3D software city vs semantic component assembly for source→capability mapping.
- Animated execution flow vs timed span waterfall for latency and incident reconstruction.
- Physical CAD/scene import vs simplified schematic for mechanical tolerance queries.
- Stable home layout vs adaptive layout for repeated sessions and changed baselines.
- Browser scene vs accessible list/keyboard flow for every mandatory task.

**Rejection condition:** do not ship a metaphor that raises false certainty, hides edges, breaks source inspection, degrades task correctness, or requires inaccessible pointing/VR to perform core navigation. This is a hypothesis register, not evidence of an optimal universal representation.
